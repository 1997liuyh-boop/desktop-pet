# 稳定化优化设计

## 目标

本轮只处理稳定性与运行链路收敛，不扩展玩法，不重做人设，不调整视觉风格。

目标是让项目优先以 Tauri v2 稳定运行，并减少前端业务逻辑对 Electron、本机绝对路径和散落存储位置的依赖。

## 范围

### 运行入口

- `npm run dev` 和 `npm run build` 继续以 Tauri 为主入口。
- Electron 相关文件暂时保留，不在本轮删除。
- 前端新增运行时适配边界，后续模块优先依赖统一能力，而不是直接判断具体运行时。

### 资源加载

- manifest 继续作为动画资源索引。
- 前端不再把 `D:/demo3/VPet/...` 作为业务层硬依赖。
- Tauri 环境优先通过后端命令读取 manifest 和 PNG 帧。
- 浏览器预览环境保留相对路径 fallback，方便轻量调试。

### 状态持久化

- 宠物状态、行为配置、AI 配置统一通过运行时适配层读写。
- Tauri 环境由后端负责文件位置。
- 浏览器预览环境用 localStorage fallback。

### 窗口能力

- 窗口移动、位置读取、点击穿透等桌面能力收敛到适配层。
- 不支持的环境返回安全默认值，不让主循环崩溃。

## 非目标

- 不删除 Electron 入口。
- 不做 UI 大改。
- 不增加新玩法系统。
- 不重写 Rust 侧完整状态机。

## 验证方式

- manifest 能加载。
- 常用动画能预加载。
- 宠物主界面能启动并进入循环。
- 状态保存和恢复不抛异常。
- Tauri 桌面窗口移动能力不被破坏。

## 实施顺序

1. 增加前端运行时适配层。
2. 将资源读取、状态保存、窗口操作接入适配层。
3. 去掉主流程中的本机绝对资源路径硬依赖。
4. 对最近改动文件做静态诊断和一次基础启动验证。
